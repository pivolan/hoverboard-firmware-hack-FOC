# Стратегия ограничения ускорения через управление током

## Параметры системы

### Механические параметры
- **Диаметр колес**: 10 дюймов (254 мм)
- **Радиус колес**: r = 127 мм = 0.127 м
- **Длина окружности**: L = 2πr ≈ 0.798 м

### Электрические параметры
- **Напряжение**: 42 В
- **Максимальный ток на мотор**: 15 А
- **Максимальная мощность на мотор**: P_max = 42V × 15A = 630 Вт

### Параметры управления
- **Период главного цикла**: DELAY_IN_MAIN_LOOP = 5 мс
- **Частота обновления**: f = 200 Гц
- **Формат данных скорости**: n_mot в RPM (обороты в минуту)

## Рекомендуемые лимиты ускорения

### Комфортные ускорения для человека

**Стоя:**
- **Максимально комфортное**: 0.5 - 1.0 м/с² (практически незаметно)
- **Умеренное**: 1.0 - 1.5 м/с² (легкое отклонение, нужен баланс)
- **Спортивное**: 1.5 - 2.5 м/с² (активное удержание равновесия)
- **Агрессивное**: 2.5 - 4.0 м/с² (сильное отклонение, требуется хорошая подготовка)

**Сидя:**
- **Максимально комфортное**: 1.0 - 2.0 м/с²
- **Умеренное**: 2.0 - 3.0 м/с²
- **Спортивное**: 3.0 - 5.0 м/с²

**Рекомендация для универсального использования**:
- **1.2 м/с²** - оптимальный баланс между комфортом стоя и динамикой

### Сравнение с другими транспортными средствами
- Лифт: 0.5 - 1.0 м/с²
- Городской транспорт (автобус, метро): 1.0 - 1.5 м/с²
- Легковой автомобиль (комфортная езда): 2.0 - 3.0 м/с²
- Спортивный автомобиль: 5.0 - 10.0+ м/с²

## Измерение ускорения

### Формулы пересчета

**1. Линейная скорость из RPM:**
```
v = (n_mot / 60) × L
где:
  v - линейная скорость [м/с]
  n_mot - обороты мотора [RPM]
  L - длина окружности колеса [м]
```

**2. Ускорение из разницы скоростей:**
```
a = Δv / Δt = (v_current - v_previous) / 0.005
где:
  a - ускорение [м/с²]
  Δt = 5 мс = 0.005 с
```

**3. Упрощенная формула для расчета в коде:**
```
a = (n_mot_current - n_mot_previous) × K
где:
  K = L / (60 × 0.005) = 0.798 / 0.3 ≈ 2.66
```

### Фильтрация и усреднение

**Проблема**: Измерение ускорения на интервале 5 мс может давать шумные данные и рывки.

**Решения:**

1. **Скользящее окно усреднения** (рекомендуется):
   - Усреднять скорость за последние N измерений (N = 4-10)
   - Период усреднения: 20-50 мс
   - Преимущества: плавность, устойчивость к шуму
   - Недостатки: небольшая задержка реакции

2. **Экспоненциальный фильтр низких частот**:
   ```
   v_filtered = α × v_current + (1 - α) × v_filtered_prev
   где α = 0.2 - 0.4 (коэффициент фильтрации)
   ```

3. **Расчет ускорения на большем интервале**:
   - Сравнивать скорость через каждые 20-40 мс (4-8 шагов)
   - Более точная оценка среднего ускорения
   - Меньше влияние краткосрочных флуктуаций

**Рекомендация**: Комбинация методов 1 и 3 - скользящее окно из 6 измерений (30 мс) с расчетом ускорения.

## Связь между током и ускорением

### Физическая модель

**1. Крутящий момент от тока:**
```
T = k_t × i_q
где:
  T - крутящий момент [Н·м]
  k_t - константа момента мотора [Н·м/А]
  i_q - ток по оси Q (создающий момент) [А]
```

**2. Сила на колесе:**
```
F = T / r
где:
  F - тяговая сила [Н]
  r - радиус колеса [м]
```

**3. Ускорение:**
```
a = F / m_total = (k_t × i_q) / (m_total × r)
где:
  m_total - общая масса (борд + человек) [кг]
```

**4. Связь ток-ускорение:**
```
i_q ≈ (m_total × r × a) / k_t
```

### Тип зависимости

**Ответ: ЛИНЕЙНАЯ зависимость** между током и ускорением

**Обоснование:**
- Момент мотора линейно пропорционален току (T ∝ i_q)
- Ускорение линейно пропорционально силе (a ∝ F)
- Следовательно: a ∝ i_q

**НО**: Есть нелинейные эффекты:
1. **Трение качения** (увеличивается с ростом скорости)
2. **Аэродинамическое сопротивление** (F_drag ∝ v²)
3. **Потери в моторе** (растут с током и скоростью)
4. **Насыщение магнитной системы** (при высоких токах)

**Вывод**: В первом приближении используем линейную модель, но для точности можно добавить квадратичную коррекцию.

## Стратегия ограничения тока

### Алгоритм управления

**Шаг 1: Измерение текущего ускорения**
```c
// Скользящее окно для усреднения скорости (6 элементов = 30 мс)
static int16_t speed_history[6] = {0};
static uint8_t speed_index = 0;

// Обновление истории
speed_history[speed_index] = rtY_Left.n_mot;  // или среднее левого и правого
speed_index = (speed_index + 1) % 6;

// Средняя скорость за текущий период
int32_t speed_avg_current = 0;
for(int i = 0; i < 6; i++) {
    speed_avg_current += speed_history[i];
}
speed_avg_current /= 6;

// Предыдущая средняя скорость (сохраненная 30 мс назад)
static int32_t speed_avg_previous = 0;

// Ускорение в RPM/(30 мс) → нужно пересчитать в м/с²
int32_t accel_rpm_per_30ms = speed_avg_current - speed_avg_previous;
speed_avg_previous = speed_avg_current;

// Пересчет в м/с²: a = Δn × (L/60) / 0.03
// a = Δn × 0.798 / (60 × 0.03) = Δn × 0.443
int32_t accel_mm_s2 = (accel_rpm_per_30ms * 443) / 1000;  // в мм/с²
```

**Шаг 2: Сравнение с лимитом**
```c
#define ACCEL_LIMIT_MM_S2  1200  // 1.2 м/с² = 1200 мм/с²

int32_t accel_error = accel_mm_s2 - ACCEL_LIMIT_MM_S2;

if (accel_error > 0) {
    // Ускорение превышает лимит - нужно уменьшить ток
}
```

**Шаг 3: Расчет коррекции тока**

**Вариант A: Пропорциональное управление (простое, рекомендуется)**
```c
// Линейная коррекция тока пропорционально превышению ускорения
int16_t current_correction = (accel_error * K_ACCEL) / 1000;

// K_ACCEL подбирается экспериментально
// Примерное значение: K_ACCEL = 500-1000
// Чем больше K_ACCEL, тем агрессивнее ограничение

int16_t new_i_max = currentLimit - current_correction;

// Ограничение минимального тока (чтобы не заглушить совсем)
if (new_i_max < MIN_CURRENT_LIMIT) {
    new_i_max = MIN_CURRENT_LIMIT;
}

rtP_Left.i_max = rtP_Right.i_max = new_i_max;
```

**Вариант B: PI-регулятор (более точный)**
```c
static int32_t accel_error_integral = 0;

// Пропорциональная составляющая
int32_t p_term = (accel_error * K_P) / 1000;

// Интегральная составляющая (накопление ошибки)
accel_error_integral += accel_error;
if (accel_error_integral > MAX_INTEGRAL) accel_error_integral = MAX_INTEGRAL;
if (accel_error_integral < -MAX_INTEGRAL) accel_error_integral = -MAX_INTEGRAL;
int32_t i_term = (accel_error_integral * K_I) / 10000;

// Сброс интегратора при отпускании газа
if (ABS(input1[inIdx].cmd) < 10 && ABS(input2[inIdx].cmd) < 10) {
    accel_error_integral = 0;
}

int16_t current_correction = p_term + i_term;
int16_t new_i_max = currentLimit - current_correction;

// Коэффициенты подбираются экспериментально:
// K_P = 500-1500 (быстрота реакции)
// K_I = 50-200 (точность удержания)
```

**Вариант C: Нелинейная коррекция (для учета потерь)**
```c
// Квадратичная компонента для учета аэродинамики
int32_t accel_error_squared = (accel_error * accel_error) / 1000;
int16_t nonlinear_term = (accel_error_squared * K_NL) / 10000;

int16_t current_correction = (accel_error * K_P) / 1000 + nonlinear_term;
```

### Формула коррекции (итоговая рекомендация)

**Гибридный подход: Линейная основа + квадратичная коррекция**

```c
// Основная линейная коррекция (быстрая реакция)
int32_t linear_correction = (accel_error * K_LINEAR) / 1000;

// Нелинейная коррекция (для сильных превышений)
int32_t quad_correction = 0;
if (accel_error > 500) {  // Только при превышении > 0.5 м/с²
    int32_t excess = accel_error - 500;
    quad_correction = (excess * excess * K_QUAD) / 1000000;
}

// Итоговая коррекция
int16_t total_correction = linear_correction + quad_correction;

// Применение с ограничениями
int16_t new_i_max = currentLimit - total_correction;
new_i_max = CLAMP(new_i_max, MIN_CURRENT_LIMIT, maxCurrentLimit);

rtP_Left.i_max = rtP_Right.i_max = new_i_max;
```

**Рекомендуемые коэффициенты для начальной настройки:**
- `K_LINEAR = 800` - основная линейная связь
- `K_QUAD = 50` - квадратичная коррекция (слабая)
- `MIN_CURRENT_LIMIT = (3 * A2BIT_CONV) << 4` - минимум 3А (для удержания)

## Особенности реализации

### 1. Раздельное управление левым и правым колесом

При повороте колеса вращаются с разной скоростью. Варианты:

**A. Независимое ограничение каждого колеса:**
```c
// Отдельные лимиты для каждого мотора
rtP_Left.i_max = calculate_limit(accel_left);
rtP_Right.i_max = calculate_limit(accel_right);
```
- Преимущества: точное управление, лучше на поворотах
- Недостатки: сложнее реализация

**B. Ограничение по максимальному ускорению:**
```c
// Берем максимальное ускорение из двух колес
int32_t accel_max = MAX(accel_left, accel_right);
int16_t limit = calculate_limit(accel_max);
rtP_Left.i_max = rtP_Right.i_max = limit;
```
- Преимущества: простота, симметричность
- Недостатки: может ограничивать медленное колесо

**C. Ограничение по среднему ускорению (рекомендуется):**
```c
// Среднее ускорение обоих колес
int32_t accel_avg = (accel_left + accel_right) / 2;
int16_t limit = calculate_limit(accel_avg);
rtP_Left.i_max = rtP_Right.i_max = limit;
```
- Преимущества: баланс между точностью и простотой
- Лучше всего для большинства сценариев

### 2. Взаимодействие с существующим soft start/stop

Существующий код (main.c:361-387) управляет `i_max` для плавного старта/останова.

**Интеграция:**
```c
// Сначала применяется soft start/stop (как сейчас)
if (enable == 1 && throttle_released) {
    currentLimit -= currentRampStepDown;
    // ...
} else if (enable == 1 && throttle_pressed) {
    currentLimit += currentRampStepUp;
    // ...
}

// ЗАТЕМ применяется ограничение по ускорению
int16_t accel_limited_current = apply_acceleration_limit(currentLimit);

// Финальное применение
rtP_Left.i_max = rtP_Right.i_max = accel_limited_current;
```

**Важно**: Ограничение по ускорению должно работать ПОВЕРХ soft start, только уменьшая ток при необходимости.

### 3. Режимы работы

**A. Только при разгоне (рекомендуется для начала):**
```c
if (accel_mm_s2 > ACCEL_LIMIT_MM_S2) {
    // Применить ограничение
}
```

**B. При разгоне и торможении:**
```c
if (ABS(accel_mm_s2) > ACCEL_LIMIT_MM_S2) {
    // Применить ограничение
}
```

**C. Адаптивный режим (режимы езды):**
```c
int16_t accel_limit;
switch(drive_mode) {
    case COMFORT_MODE:  accel_limit = 1000; break;  // 1.0 м/с²
    case NORMAL_MODE:   accel_limit = 1500; break;  // 1.5 м/с²
    case SPORT_MODE:    accel_limit = 2500; break;  // 2.5 м/с²
}
```

### 4. Отключение при экстренных ситуациях

Ограничение ускорения НЕ должно работать:
- При emergency stop (ошибки, перегрев)
- При срабатывании других защит
- При низком напряжении батареи

```c
if (!enable || rtY_Left.z_errCode || rtY_Right.z_errCode ||
    batVoltage < BAT_LVL2) {
    // Отключить ограничение ускорения
    return currentLimit;  // Без изменений
}
```

## Возможные проблемы и решения

### Проблема 1: Колебания (oscillations)
**Причина**: Слишком агрессивная коррекция или недостаточная фильтрация

**Решение**:
- Увеличить окно усреднения (до 10 элементов)
- Уменьшить K_LINEAR
- Добавить гистерезис

### Проблема 2: Слишком слабое ограничение
**Причина**: Неправильный коэффициент или фильтрация съедает пики

**Решение**:
- Увеличить K_LINEAR
- Уменьшить окно усреднения
- Добавить квадратичную составляющую

### Проблема 3: Рывки при переходах
**Причина**: Резкое изменение лимита тока

**Решение**:
- Rate limiter для самого лимита тока
- Постепенное применение коррекции

```c
static int16_t i_max_filtered = maxCurrentLimit;
int16_t i_max_target = calculate_new_limit();

// Плавное изменение лимита
if (i_max_target < i_max_filtered) {
    i_max_filtered -= CURRENT_LIMIT_RAMP_DOWN;
    if (i_max_filtered < i_max_target) i_max_filtered = i_max_target;
} else {
    i_max_filtered += CURRENT_LIMIT_RAMP_UP;
    if (i_max_filtered > i_max_target) i_max_filtered = i_max_target;
}
```

### Проблема 4: Недостаточная мощность на горках
**Причина**: Ограничение не учитывает уклон

**Решение**: Добавить компенсацию по углу наклона (если есть акселерометр)

```c
// Компенсация гравитации: a_real = a_measured - g × sin(θ)
int32_t gravity_compensation = (g * sin_angle * 1000) / 1000;
int32_t accel_compensated = accel_measured - gravity_compensation;
```
